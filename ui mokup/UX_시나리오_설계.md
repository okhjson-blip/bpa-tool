# 업무 프로세스 분석 툴 — UX 시나리오 설계

> **목적**: AI 적용을 통한 프로세스 자동화 및 재설계 방안 도출
> **사용자**: 컨설턴트 + 담당자 (같은 화면에서 함께 작업 · 참여자는 역할[리더/담당자/컨설턴트]로 구분하여 등록)
> **형태**: 웹 앱 (브라우저, 데스크탑 최적화 · 14인치 Full Screen 기준 레이아웃 최적화)
> **분석 방법**: STATIK (L1~L6 업무 분해) → BDW (병목/지연/낭비 진단) → AI FIT 스코어 매트릭스
> **시각화**: 테이블 편집 + 플로우차트 병행, 좌우 3:2 분할 (As-Is/To-Be 비교 화면만 1:1 동일 분할)
> **AI 엔진**: Gemini / ChatGPT / Claude 중 선택 + API Key 직접 입력 (외부 API)
> **계정/인증**: 불필요 · **다국어**: 미지원

---

## 전체 흐름

```
프로젝트 목록                프로젝트 단위 관리 (회사/부서/기간/AI엔진/참여자)
   ↓ (+ 새 프로젝트 / 기존 프로젝트 클릭)
과제 목록                    프로젝트 하위, 과제(L4) 단위 관리
   ↓ (+ 새 과제(L4) / 기존 과제 클릭)
Step 1. 과제 등록 (L4)       STATIK L1~L4 입력 + 참여자(과제 리더/담당자) 등록
   ↓
Step 2. 인터뷰 & Draft       기본 질문 5개에 타이핑 답변 → AI가 L4~L6 자동 분해
   ↓
Step 3. 프로세스 수정        테이블 + 플로우차트 직접 편집 (양방향 동기화, 3:2 분할)
   ↓
Step 4. BDW 진단            Bottleneck / Delay / Waste 태그 부착 및 요약
   ↓
Step 5. AI FIT 분석         AI 적용 가능성 × 비효율성 매트릭스 (As-Is/To-Be 1:1 비교)
   ↓
Step 6. 결과 리포트         AX 성과 지표(FTE) + 외주 개발비 + 출력
   ↓
[이전] [과제 목록으로] [프로젝트 목록으로]   ← 하단 공통 푸터, Step 6에서는 마지막 버튼이 "프로젝트 목록으로"
```

> **탐색 구조**: 상단 헤더의 브레드크럼(프로젝트 목록 › 프로젝트명 › 과제명)과 스텝바(과제 등록~결과 리포트)가 항상 노출되며, 스텝바 하단에는 현재 과제의 L1›L2›L3›L4 컨텍스트 칩이 표시됩니다. 프로젝트/과제 목록 화면에서는 스텝바·컨텍스트칩·하단 푸터가 숨겨지고 목록 전용 브레드크럼으로 전환됩니다.

## STATIK 업무 분해 계층 정의

| 레벨 | 구분명 | 설명 | 입력 단계 | 예시 |
|------|--------|------|----------|------|
| **L1** | 구분 (조직 기능) | 기업 밸류체인 영역 | Step 1 (과제 등록) 텍스트 입력 | 영업마케팅, 연구개발, 제조, 경영지원 |
| **L2** | 대분류 (업무 도메인) | 도메인별 핵심 프로세스 | Step 1 (과제 등록) 텍스트 입력 | 디지털마케팅, 마케팅기획 |
| **L3** | 기능 (핵심 기능) | 목적별 세부 기능 | Step 1 (과제 등록) 텍스트 입력 | 콘텐츠 제작, SNS 채널 운영, 캠페인 기획 |
| **L4** | 모듈 (업무 묶음) | 실제로 관리·인식되는 관련 업무의 묶음 · **과제 등록 단위** | Step 1 (과제 등록) 텍스트 입력 | SNS 채널 관리 |
| **L5** | 단위 업무 (독립 업무) | "이 일을 했다"고 말할 수 있는 독립적 결과물이 나오는 업무 | Step 2 인터뷰 답변 → AI Draft 자동 분해 | 게시물 기획, 게시물 제작, 게시물 승인, 게시물 발행 |
| **L6** | Action (최소 행위) | 더 이상 쪼갤 수 없는 사람의 실제 행동 단위. **수행 시간(분) 필수 입력** | Step 2 인터뷰 답변 → AI Draft 자동 분해 | 트렌드 키워드를 검색한다(10분), 초안을 입력한다(30분) |

> **L6 입력 규칙**: 액션명은 "목적어 + 동사" 형태. 수행 시간(분)은 필수 입력.
> L4/L5 소요시간은 하위 항목 수행 시간의 합으로 자동 집계.
> **계층별 정의 팝업(?)**: Step 1·2·3 화면의 카드 제목 옆 ? 버튼 클릭 시 L1~L6 전체 정의(뜻/설명/예시)를 팝업으로 참조 가능.

## 프로젝트 목록

**화면**: 프로젝트 카드 리스트 + [+ 새 프로젝트] 버튼

| 최근 수정 일자 | 카드 우측 상단 표기 |

카드 클릭 시 해당 프로젝트의 **과제 목록**으로 이동. 카드 리스트 하단에는 점선 테두리의 [+ 새 프로젝트 생성하기] 카드를 추가 배치.

### 새 프로젝트 생성 폼

| 카드 | 항목 | 입력 방식 | 비고 |
|------|------|----------|------|
| 기본 정보 | 회사명 | 텍스트 | 필수 |
| 기본 정보 | 부서명 | 텍스트 | 선택 |
| 기본 정보 | 프로젝트명 | 텍스트 | 필수 |
| 기본 정보 | 프로젝트 기간 | 날짜 범위 | 선택 |
| 기본 정보 | 프로젝트 목적 | 텍스트 | 선택 |
| AI 엔진 설정 | AI 엔진 | 카드 선택 | Gemini / ChatGPT / Claude |
| AI 엔진 설정 | API Key | 텍스트 (마스킹) | 필수. [연결 테스트] 버튼으로 즉시 유효성 검증 |
| 참여자 등록 | 이름 · 직급 · 역할 · 이메일 | 행 반복 입력 | 역할은 드롭다운: **프로젝트 리더 / 프로젝트 담당자 / 컨설턴트**. [+ 참여자 추가]로 행 추가 |

[취소] / [프로젝트 생성 →] 버튼으로 마무리 → 생성 즉시 해당 프로젝트의 과제 목록으로 이동.

## 과제 목록

**화면**: 프로젝트 정보 요약 카드 + 과제 카드 리스트 + [+ 새 과제 (L4)] 버튼

### 프로젝트 정보 카드

회사·부서, 목적, 기간, AI 엔진, 참여자(이름+역할)를 칩으로 요약 표기.

### 과제 카드 구성

| 항목 | 내용 |
|------|------|
| 과제명 (L4) | 카드 제목, "(L4)" 표기 |
| 경로 | L1 › L2 › L3 (소속 상위 계층) |
| 상태 | 상태 칩: ✓ 리포트 완료 / 진행중 · 현재 단계 / 등록 대기 |
| 최근 수정 일자 | 카드 우측 하단 |

카드 클릭 시 해당 과제의 마지막 진행 단계(Step)로 바로 이동. 리스트 하단에 점선 테두리의 [+ 새 과제 등록하기 (L4 단위)] 카드 배치.

## Step 1. 과제 등록 (L4)

**주요 사용자**: 컨설턴트 + 담당자 (함께 진행 가능)
**화면**: STATIK L1~L4 입력 폼 + 과제 정보 + 참여자 등록

### 입력 항목

| 카드 | 항목 | 입력 방식 | 비고 |
|------|------|----------|------|
| 과제 등록 | L1 구분 (조직 기능) | 텍스트 | 필수. 예: 영업마케팅 |
| 과제 등록 | L2 대분류 (업무 도메인) | 텍스트 | 필수. 예: 디지털마케팅 |
| 과제 등록 | L3 기능 (핵심 기능) | 텍스트 | 필수. 예: 콘텐츠 제작 |
| 과제 등록 | L4 과제명 (모듈) | 텍스트 | 필수. 예: SNS 채널 관리 |
| 과제 등록 | 과제명 | 텍스트 | 필수. L4와 별도로 과제 자체의 이름 지정 (예: "SNS 채널 관리 프로세스 분석") |
| 과제 등록 | 과제 기간 | 날짜 범위 | 선택 |
| 과제 등록 | 과제 목표 | 텍스트 | 선택 |
| 참여자 등록 | 이름 · 직급 · 역할 · 이메일 | 행 반복 입력 | 역할은 드롭다운: **과제 리더 / 과제 담당자**. [+ 참여자 추가]로 행 추가 |

[취소] / [과제 등록 → 인터뷰 시작 →] 버튼으로 Step 2로 이동.

### ? 팝업 위치

"과제 등록" 카드 제목 옆 → L1~L6 계층 전체 정의 팝업

## Step 2. 인터뷰 & Draft

**주요 사용자**: 컨설턴트 + 담당자 (같은 화면, 함께 진행)
**화면**: 인터뷰 질문·답변 입력 → AI Draft 생성

> **인터뷰 방식 선택 단계 없음**: 녹음/파일 업로드 없이, 기본 질문에 대한 담당자 답변을 곧바로 텍스트로 입력(타이핑)합니다.

### 인터뷰 질문 (5개, STATIK + BDW 관점)

| # | 질문 | 분석 관점 |
|---|------|----------|
| 1 | 이 업무는 누가 어떤 순서로 어떻게 진행되고 얼마나 시간이 걸리나요? | L3 흐름 파악 |
| 2 | 단위 업무 중 반복적으로 수행하거나 항상 쌓이는 단계는? | Bottleneck |
| 3 | 승인/검토/확인/전달 때문에 기다리는 시간이 발생하는 구간과 대기시간은? | Delay |
| 4 | 하지 않아도 결과가 크게 달라지지 않는 작업이 있나요? | Waste |
| 5 | 고객/이해관계자는 누구이고 어떤 불편을 겪나요? | 고객 관점 |

각 질문 카드 아래 "담당자 답변" 입력창(textarea)에 자유 텍스트로 답변을 작성. [+ 질문 추가] 버튼으로 질문 항목 추가 가능.

### AI Draft 자동 생성

[✨ AI Draft 생성 →] 클릭 → 입력된 답변 텍스트 분석 → STATIK L4~L6 계층 자동 분해 → 테이블 생성 (하단 "AI 생성 Draft" 카드, 생성 완료 시 "✓ 생성 완료" 표기)

### Draft 테이블 컬럼 구성

| 컬럼 | 내용 |
|------|------|
| 레벨 | 칩 표시 · L4 모듈 / L5 단위 / L6 Act |
| 단위 업무명 | L6는 "목적어+동사" 가이드 |
| 작업방식 | 수작업 / 시스템 |
| 사용도구 | Excel / Doc / System / Web / 기타 |
| 수행시간(분) | L6 필수 |
| 승인대기(h) | 결재·승인 대기 시간 |

테이블 하단에 "수행시간 합계 / 승인 대기" 요약 표시 + [프로세스 수정 단계로 →] 버튼으로 Step 3 이동.

### ? 팝업 위치

"인터뷰 진행" 카드 제목 옆 / "AI 생성 Draft" 카드 제목 옆

## Step 3. 프로세스 수정

**주요 사용자**: 컨설턴트 + 담당자 (역할 구분 없이 공동 편집)
**화면**: 상단 편집 툴바 + 좌측(60%) 편집 가능 테이블 + 우측(40%) SVG 플로우차트 — **3:2 좌우 분할**, 양방향 동기화

### 편집 툴바

[+ 행 추가] [⬆ 위로] [⬇ 아래로] [✕ 삭제] · [↕ 레벨 변경] [📐 플로우차트 동기화] · 우측에 자동저장 상태("✓ 자동저장됨 hh:mm") 표시

### 테이블 편집 (좌측)

| 컬럼 | 편집 방식 |
|------|----------|
| 레벨 | 칩 표시 (L4/L5/L6, 들여쓰기로 계층 표현) |
| 단위 업무명 | 텍스트 |
| 작업방식 | 드롭다운: **수작업 / 시스템** |
| 사용도구 | 드롭다운: **System / Doc / Excel / Web / 기타** |
| 수행(분) | 숫자 key-in |
| 대기(h) | 숫자 key-in |
| 승인대기(h) | 숫자 key-in (지연 발생 시 강조 표시) |

행 좌측 ⋮⋮ 핸들로 Drag & Drop 이동 가능. 하단에 "수행시간 합계 / 승인 대기" 요약 + [BDW 진단 →] 버튼.

### 플로우차트 (우측)

테이블과 동일한 계층·데이터를 SVG 플로우차트로 시각화 (L4 모듈 → L5 단위 → L6 Act 순서의 세로 흐름, 화살표로 연결). 카드 안내문구: "노드 더블클릭: 편집 | 우클릭: 메뉴 | 드래그: 이동/삽입" — 테이블 수정 시 플로우차트에 동일 계층·값이 반영되는 양방향 동기화 구조.

### ? 팝업 위치

"프로세스 테이블" 카드 제목 옆

## Step 4. BDW 진단

**주요 사용자**: 컨설턴트 + 담당자
**화면**: BDW 요약 카드 4개 + BDW 태그 부착 테이블 + 진단 요약

### BDW 태그 정의

| 태그 | 의미 | 진단 기준 |
|------|------|----------|
| 🔴 Bottleneck | 처리량 < 유입량, 전체 속도 제한 | 일이 항상 쌓이거나 반복 지연 |
| 🟡 Delay | 대기·승인·전달로 인한 시간 손실 | 대기(h) + 승인대기(h) 분리 집계 |
| ⚫ Waste | 고객 가치 미기여 활동 | 없애도 결과가 크게 달라지지 않는 작업 |
| ✅ 정상 | 비효율 없음 | — |

### 상단 요약 카드 (4개)

| 카드 | 표시 내용 |
|------|----------|
| 🔴 Bottleneck | 개수 + 대표 단계명 |
| 🟡 Delay | 개수 + 대기(h)/승인대기(h) 내역 |
| ⚫ Waste | 개수 |
| ⏱ 비효율 지수 | 전체 시간 대비 비효율 비율(%) |

### 태그 부착 테이블

레벨 / 단위 업무명 / 수행(분) / 대기(h) / 승인대기(h) / BDW 태그(드롭다운 선택) 컬럼으로 구성. 하단에 "🔍 BDW 진단 요약" 텍스트 박스로 핵심 병목·지연 사유를 자동 요약 표기.

[← 돌아가서 수정] / [✓ 프로세스 확정 & AI FIT 분석 →] 버튼으로 마무리.

## Step 5. AI FIT 분석

**주요 사용자**: AI + 컨설턴트 + 담당자 (결과 검토)
**화면**: 상단 요약 카드 4개 + 3탭(인라인 분석 / 매트릭스 뷰 / As-Is vs To-Be)

### AI FIT 스코어 매트릭스

| 축 | 점수 | 의미 |
|----|------|------|
| **AI 적용 가능성** | 1~5 | 1: 적용 어려움 → 5: 완전 자동화 가능 |
| **비효율성** | 1~5 | 1: 효율적 → 5: 매우 비효율 (BDW 결과 연동) |

각 점수 척도의 상세 정의는 카드 제목 옆 ? 버튼 → "AI FIT 스코어 척도 안내" 팝업에서 1~5점 각각의 기준을 확인 가능.

### 분류 기준 (A/B/C/D)

| 분류 | 기준 | 권장 액션 |
|------|------|----------|
| **A (즉시 적용)** | AI 가능성 높음 + 비효율 높음 | AI 개발 우선 착수 |
| **B (수동 개선 先)** | AI 가능성 낮음 + 비효율 높음 | 프로세스 개선 후 AI 검토 |
| **C (장기 검토)** | AI 가능성 높음 + 비효율 낮음 | 기술·환경 성숙 후 검토 |
| **D (현상 유지)** | AI 가능성 낮음 + 비효율 낮음 | 개선 우선순위 낮음 |

### 상단 요약 카드 (4개)

전체 L6 업무 수 / A영역 개수 / 예상 자동화율 / 절감 시간(건당, 현재→AI적용 후)

### 탭 구성

**탭 1. 📋 인라인 분석 (테이블)**
각 L6 Action 행에 AI 적용 가능성 점수 / 비효율성 점수 / 분류(A~D) / 추천 AI 기술 / 절감(분) 컬럼 표시. 점수는 원형 배지(1~5)로 색상 구분. 하단 [AI 제안 선택 수락] / [✓ 전체 수락 후 To-Be 반영] 버튼.

**탭 2. 📊 매트릭스 뷰**
2×2 그리드(A/B/C/D 영역, 색상 구분) 위에 각 업무를 칩으로 배치. X축: AI 적용 가능성(낮음→높음), Y축: 비효율성(낮음→높음, 세로 축 레이블).

**탭 3. 🔄 As-Is vs To-Be** — 좌우 **1:1 동일 크기 분할** (다른 화면의 3:2 분할과 다른 예외 규칙)
좌측(As-Is, 빨강 계열): 현재 상태 플로우차트 + 하단 "총 XX분 + XXh 대기" 표기.
우측(To-Be, 초록 계열): AI 적용 후 재설계 플로우차트. 각 노드에 적용 AI 기술(🤖 아이콘)과 단축된 소요시간을 함께 표시하고, 최하단에 "총 XX분 + XXh 대기 🎉"로 절감 결과 표기.

하단 [결과 리포트 생성 →] 버튼으로 Step 6 이동.

## Step 6. 결과 리포트

**주요 사용자**: 컨설턴트 + 담당자
**화면**: 좌측(60%) 리포트 구성 + 출력 형식 / 우측(40%) AX 성과 지표 — **3:2 좌우 분할**

### 리포트 구성 섹션 (체크박스 선택)

| 섹션 | 내용 |
|------|------|
| STATIK 업무 구조 (L1~L3) | 업무 계층 구조 요약 |
| As-Is 프로세스 | 테이블 + 플로우차트 |
| BDW 진단 결과 | 병목·지연·낭비 위치 및 요약 |
| AI FIT 분석 + To-Be 재설계 | 스코어 매트릭스, 분류 결과, To-Be 플로우차트 |
| AX 성과 지표 (FTE 기반) | 아래 참조 |
| 변경 이력 (선택) | 기본 미체크 |

카드 하단 커스터마이징 영역에서 보고서 제목 텍스트 입력, 로고 파일 업로드([📁 파일 선택]) 가능.

### 출력 형식

4개 버튼: 📊 PowerPoint / 📄 Word / 📕 PDF / 🔗 웹 링크(읽기 전용 공유)

### AX 성과 지표

> **핵심 원칙**: AX 성과는 "시간 절감"이 아니라 **FTE(Full-Time Equivalent)** 단위로 측정.

#### ① 핵심 지표 (FTE 기반)

| 항목 | 산출 방식 |
|------|----------|
| AX 절감 시간 (h) | 소요시간 합계 × 자동화율 (Step 5 자동 연산) |
| **절감 FTE** | AX 절감 시간 ÷ **2,248h** (전사 연간 표준 근무시간) |
| FTE 비율 (%) | 절감 FTE ÷ 조직 인원 수 × 100 |

강조 박스(진한 배경)에 산식과 절감 FTE 값을 크게 표시. 보조 스코어 카드로 절감 시간(건당) / FTE 비율 / 자동화율을 나란히 표기.

#### ② FTE 활용 계획 (필수 입력)

| 유형 | 설명 |
|------|------|
| 새로운 일 확대 | 신규 과제 / 전략과제 / 해외과제 이관 / 내재화 |
| 커리어 전환 | 구성원 타부서 이동 / 잡포스팅 |
| 잔특근 절감 | 초과근무 감소 → 근무시간 축소 |

각 유형별로 배분 FTE 값과 활용 내용을 카드로 표시.

#### ③ 보조 지표

| 지표 | 산출 방식 |
|------|----------|
| 토큰비 | AI/토큰 비용 ÷ 절감 FTE |
| 프로세스 재설계 수준 | L3~L5 구조 변화 여부 (AI FIT To-Be 기반 자동 판정) |
| Human-AI 역할 비중 | Human Touch / AI Augment / AI Automation 비율 |
| **외주 개발비 추정** | A영역 개수 × 1.0 M/M × 월 노임단가 (아래 산식) |

**외주 개발비 산출 방식**

```
외주 개발비 = A영역 개수 × 1.0 M/M × (378,250원/일 × 22일)
           = A영역 개수 × 1.0 M/M × 8,321,500원/M

기준: 2026년 SW기술자 노임단가 — 응용SW개발자
     일평균 378,250원 / 시간평균 47,281원
산출 범위: 순수 인건비 기준 (제경비·기술료 미포함)
M/M 기준: A영역 1개 = 1.0 M/M (업무 자동화 기본값, 실제 복잡도에 따라 조정 가능)
```

강조 박스에 산출 금액 + 산식 + 기준 각주를 함께 표기.

#### ④ 성과 검증 3단계

| 단계 | 내용 |
|------|------|
| 1. 목표 수립 | FTE 목표 설정 + 활용 계획 확정 |
| 2. 과제 진행 | AI Agent 개발 / 프로세스 재설계 |
| 3. 과제 종료 | FTE 성과 측정 + 활용 결과 보고 + ROI 검토 |
